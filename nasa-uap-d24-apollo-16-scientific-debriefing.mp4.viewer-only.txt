Why no file: this is NOT a war.gov or DVIDS problem. The asset downloads fine and
verifies (size matches the DVIDS API, ftyp box present at offset 4). GitHub's LFS API
rejects it:

  [6802ea02...] Size must be less than or equal to 2147483648: [422]

2147483648 bytes is 2 GiB, a hard per-object ceiling on GitHub LFS. At 3.20 GB this
record cannot be stored in this repository as a single object. Every other file in the
corpus is under 1 GB, so this is the first record to hit the ceiling.

Resolving it requires a human decision about corpus semantics, so the watcher will not
pick one on its own. The options:
  1. Split into <2 GiB parts (e.g. .part1/.part2 plus a rejoin note). Faithful bytes,
     but the corpus would no longer be one-record-one-file.
  2. Host the single file outside GitHub and reference it from here.
  3. Store a transcoded copy under 2 GiB and keep this note pointing at the original.
  4. Leave it as a pointer — the CloudFront URL above is public and stable.

Tracked in the repo issues. The complete verified 3.20 GB file is preserved outside the
clone at ~/.local/share/uap-watcher/nasa-uap-d24-apollo-16-scientific-debriefing.mp4 so
whichever option is chosen does not require re-downloading it (it took five runs).
